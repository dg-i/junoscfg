# Template ownership and local edits

Files maintained by the agent-ready template can change during updates. Local
edits can conflict with those changes. Review the complete update diff, even
when no conflict markers remain, before accepting an update.

## Files maintained by the template

- `.agents/skills/agent-ready-*/**` and their `.claude/skills/agent-ready-*` links.
- `openspec/schemas/agent-ready/**`.
- `docs/how-to/*.md`, except the application-owned guides listed below.
- `.agent-ready/template.toml`: template version metadata; preserve application
  `[local-policy.<id>]` decisions when resolving updates.
- `.copier-answers.yml`: recorded template source, version and answers; let
  Copier maintain it rather than changing version fields by hand.
- In greenfield adoptions, `.github/workflows/ci.yml`,
  `.github/workflows/update.yml` and `.gitlab-ci.yml`, when selected at adoption.
  In brownfield adoptions, `agent-ready update` preserves existing copies of
  these workflows.

Headers identify maintained files. A missing header alone does not establish
application ownership; check this guide and the recorded adoption mode.

## Application-owned seeds and customization

Copier preserves existing `pyproject.toml`, `tach.toml`, `ARCHITECTURE.md`,
`.gitignore`, `.ignore`, `.pre-commit-config.yaml`, `openspec/config.yaml`,
`docs/BACKLOG.md`, `docs/VERIFICATION.md`, `docs/how-to/work-with-agents.md`,
`docs/how-to/solo-review.md`, and files under `src/` and `tests/`.
Use these configuration and policy homes for application-specific settings.
Checks can still require changes to them when the tooling evolves.

`AGENTS.md` and its `CLAUDE.md` bridge are scaffolded during onboarding and
belong to the application. Keep a short pointer to this guide in `AGENTS.md`.
Application contracts, specs, decisions and change records also belong to the
application. Rendered indexes and instruction blocks are regenerated by their
commands; edit their source data instead of the generated output.

When a maintained file needs a local edit, record the reason in the change
and expect to reconcile it at update time. Edit skills in `.agents/skills/`.
Each `.claude/skills/agent-ready-*` entry is a relative symlink to its source,
so Claude Code reads the same bytes as Codex; `agent-ready skills --regenerate`
restores those links and refreshes the copy of any other skill under
`.claude/skills/`. A checkout that cannot hold symlinks (`core.symlinks=false`)
shows each tracked link as a plain file holding its target, which Claude Code
cannot follow; `agent-ready skills` reports it. Set `core.symlinks=true` where
the platform allows it (on Windows, Developer Mode) and check the files out
again. No copy stands in for a tracked link, because the next commit would
replace the link with the copy.
An untracked mirror there is a copy that the updater keeps current itself.
For application-specific instructions, prefer `AGENTS.md` or an application
skill with a distinct name over modifying a shipped skill.

## Updating safely

Run `agent-ready update` on a clean update branch, never `copier update` on its
own: the updater keeps Copier out of `.claude/skills/` and writes the links
itself, whether the mirror is tracked or ignored. Read its report and follow
`agent-ready-refresh` to resolve conflicts and failing checks. Review the
whole diff for local customizations, including changes merged without a
conflict. Commit only after the intended application behaviour is verified.

An exact locally attested updater commit may remain within a later ordinary
application change. The lane gate and verification readiness verify the complete
updater checkpoint and exclude only paths whose comparison-base and current
states compose exactly through verified updater output. Application edits before
or after an update remain governed, including shared configuration paths. Edited
template skill bytes or modes, mixed updater commits, missing attestations and
ambiguous merge checkpoints do not gain an exemption. This does not admit the
combined history to the template-update lane or replace an application change.

A receipt records a tracked mirror link as its exact target and leaves out an
ignored, untracked mirror entry, which no Git diff carries. Receipts written by
check packages before 0.18.4 can include ignored copied mirror files. Historical
proof accepts these only through the canonical `.agents/skills/` mapping: exact
before/after source hashes and repository ignore rules in both immutable
snapshots must agree. Other absent recorded paths receive no exemption.
