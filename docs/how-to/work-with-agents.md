# Work with agents

Every change runs through the `agent-ready-change` skill, one phase per
session. Read the proposal, the specs, the tests, the agent review and the diff
in that order, and accept only once the checks and the acceptance criteria pass.

## Before editing

Read the module's `CONTRACT.md` first: it carries the invariants and what the
module is not for. Import through the package door — `tach check` and
`agent-ready interfaces` both refuse a submodule path such as
`junoscfg.display.constants.load_schema_tree`.

## What enforces what

| Where | What runs |
|---|---|
| `pre-commit`, on commit | ruff format and check, deptry, document caps, markdownlint |
| CI, on push and pull request | the suite on every interpreter the classifiers declare, derived from `pyproject.toml`; then `agent-ready check --set full --base origin/master` once |
| CI, reported but never blocking | mypy — 102 errors at adoption, see `docs/decisions/2026-10-06-adopt-mypy-strict.md` |

The default branch is `master`, not `main`, which is why
`[tool.template] base = "origin/master"` is set explicitly. Without it the
diff-reading gates resolve to a ref that does not exist and quietly pass.

`lane` fails on any branch whose diff is not covered by a change folder under
`openspec/changes/`. That is the gate that makes the workflow mandatory rather
than optional.

## Review

`CODEOWNERS` is generated by `agent-ready render codeowners` and never
hand-edited; `--check` fails on drift. It routes review — hosting settings are
what make review mandatory, and the template cannot verify them. On
`dg-i/junoscfg` the owner must configure protected branches with required pull
requests and code-owner review, and must allow the solo exception described in
[solo review](solo-review.md).

GitHub accepts any one listed owner when code-owner review is required. An
owner union never means "both must approve", and a zone's tier is not an
approval count: `anonymize` being the red zone changes how carefully it is
read, not how many approvals GitHub demands.

Reference: [GitHub code owners](https://docs.github.com/en/repositories/managing-your-repositorys-settings-and-features/customizing-your-repository/about-code-owners).
