# junoscfg.convert — contract

## Not for

Not a format-to-format shortcut: every conversion goes through the dict IR; a second path for a pair is the duplicate `ARCHITECTURE.md` calls a defect.

## Invariants

- Every supported pair round-trips through the IR without losing content — enforced by `tests/contract/test_format_matrix.py::TestEveryWriterKeepsTheIr::test_the_output_reads_back_as_the_ir`.
- XML input reuses the display kernel's `xml_to_dict()` walker; `yaml` and XML apply schema-backed leaf-list normalization at the common boundary, while JSON and `yaml-new` keep their supplied value shapes — enforced by `tests/unit/convert/test_convert_api.py::TestLeafListPromotion` and `tests/unit/convert/test_convert_api.py::TestJunosYamlReader`.
- `yaml-new` is the Junos JSON object in YAML, written and read by the JSON writer's and reader's object stages: its output loads as JSON output parses, and its input reads as the same object in JSON — enforced by `tests/contract/test_format_matrix.py::TestJunosYamlIsTheJsonObject`.
- The yaml-new reader gives an IR holding no mapping or list twice, and the JSON object stage writes a shared object out before it spells it — enforced by `tests/unit/convert/test_convert_api.py::TestJunosYamlReader::test_the_ir_of_a_shared_block_shares_nothing` and `tests/unit/convert/test_convert_api.py::TestJunosYamlWriter::test_a_shared_object_is_spelled_in_each_of_its_contexts`.
- Both YAML readers and the yaml-new writer refuse a cycle and a value nested deeper than 64 levels, the JSON reader a value nested that deep, and both YAML readers a mapping key that is not a string, before any recursive stage walks the document; configuration input is trusted (decisions 2026-10-15-configuration-input-is-trusted and 2026-10-15-yaml-nests-at-most-64-levels) — enforced by `tests/unit/convert/test_convert_api.py::TestIrYamlReader::test_a_cycle_or_a_value_past_64_levels_is_refused`, `tests/unit/convert/test_convert_api.py::TestIrYamlReader::test_a_key_that_is_not_a_string_is_named_by_its_kind`, `tests/unit/convert/test_convert_api.py::TestJsonReader::test_a_value_past_64_levels_is_refused_at_its_path` and `tests/unit/convert/test_convert_api.py::TestJunosYamlWriter::test_a_cycle_or_a_value_past_64_levels_is_refused_on_write`.
- An absolute selection hands the writer the selected statement's tags, so a selected leaf or leaf-list loads with the meaning its parent selection gives it — enforced by `tests/unit/convert/test_convert_api.py::TestPathFiltering::test_an_absolute_leaf_selection_keeps_its_tags`.
- A relative selection is written as absolute output writes it, without its path: the pipeline hands each writer the path-wrapped IR and the path — enforced by `tests/corpus/test_device_renderings.py::TestRelativeSelections::test_a_relative_selection_is_the_absolute_one_without_its_path`.
- No writer changes the IR it is given; the JSON writer normalizes its own copy — enforced by `tests/unit/convert/test_convert_roundtrip.py::TestNoWriterChangesTheIrItIsGiven::test_a_hand_built_ir_is_left_unchanged`.
- The three evidenced root/group singleton entry paths preserve arrays, children and entry tags; ordinary list/container/leaf-list/presence/keyworded name children never borrow the legacy entry fallback, while unresolved scalar positional-name cases retain it — enforced by `tests/unit/convert/test_convert_roundtrip.py::TestKeyedSingletonValidation::test_supported_statement_validates`, `tests/unit/convert/test_convert_roundtrip.py::TestSingletonNamePreservation::test_a_scalar_positional_name_keeps_its_child_key` and `tests/unit/convert/test_convert_roundtrip.py::TestKnownNameChildShapes::test_the_known_child_shape_keeps_meaning`.
- One configuration yields one IR whatever format it arrived in — enforced by `tests/contract/test_format_matrix.py::TestEveryReaderGivesTheShapeIr`.
- An incomplete set statement or leaf, a keyed entry without its key from JSON, YAML or XML, and a meta command on a partial or surplus key are kept whole and reported `UNPLACED`; set input keeps one, as its tokens, in its level's `junoscfg:unplaced` record, never at a placed node's key — enforced by `tests/unit/convert/test_set_input.py::TestAKeptStatementHasARecordOfItsOwn::test_a_bare_keyword_never_meets_its_placed_node`, `tests/unit/convert/test_field_validator.py::TestAnIncompleteStatementIsUnplaced::test_each_door_reports_it`, `tests/unit/convert/test_field_validator.py::TestAnEntryWithoutItsKeyIsUnplaced::test_each_structured_door_reports_it` and `tests/unit/convert/test_set_input.py::TestAMetaCommandIsNeverPartiallyApplied::test_a_partial_or_surplus_key_is_kept_whole`.
- An anonymizing conversion's messages and errors quote no word of the configuration — enforced by `tests/contract/test_every_message.py::TestAnAnonymizedRunQuotesNothingOfTheConfiguration`.
- Field-validation warnings are carried as diagnostics whether or not errors exist; strict conversion raises on errors only. A missing schema-mandatory field remains a warning: it may be required at commit, and the configuration loads without it — enforced by `tests/unit/convert/test_conversion_diagnostics.py::TestAFieldWarningNeedsNoError` and `tests/unit/convert/test_field_validator.py::TestMandatoryValidation::test_the_message_names_the_commit_boundary`.

## Precedent

- `junoscfg.convert.pipeline_result` — the implementation door for conversion; string-only `pipeline()` delegates to it and discards diagnostics.
- `junoscfg.convert.output.dict_walker.WalkOutput` — the strategy every new output format implements instead of walking the IR again.
- `junoscfg.convert.FORMAT_IMPLEMENTATIONS` — where a format name selects its implementation; a new format or a rename edits this table and `junoscfg.Format`, never the dispatch.
- `junoscfg.input.find_unsupported_set_brackets` — the lower-layer lexical boundary raw set readers apply before constructing the IR.
