# schema_verification — contract

Application-owned schema execution reporting; the template owns admission,
command identity, locking, caching and stability execution. Explicit qualify
uses the same readiness and candidate snapshot admission before taking capacity.

- Completion comes from actual unique setup/call/teardown reports and exit zero,
  with exact collected obligations; collection alone never completes an ID.
- Only explicit release-specific count skips are permitted, with their actual
  identity/reason and successful setup/teardown; skipped is never passed.
- Missing, empty, symlinked, unknown or mismatched inputs/versions refuse before
  pytest or public ArtifactBuilder execution.
- Repository-local subprocesses isolate inherited Git repository selectors and
  config overrides, retaining protocol authorization; commands preserve candidates
  and declared inputs; no success manifest
  survives failed execution or mutation. Historical verification evidence stays.
- Dirty admission and mutation snapshots share the installed wrapper's public
  EVIDENCE_RECORDS boundary: only its five fixed nonexecuting records at exact
  openspec/changes/<slug>/<record> paths are excluded. Every explicitly read
  policy/suite/runtime/dump/required/stability input overrides that spelling.
  Source, tasks, configuration, nested/archive records and other paths remain
  candidate inputs.
- Products come from the existing real_artifacts temporary fixture; shipped
  protected bytes agree with committed artifacts. Metadata generated_at is the
  sole semantic comparison exception. Every shard exports canonical metadata
  excluding only that timestamp. Assertion exports are consumed immutable inputs
  to a separate generation tier; its four raw products and canonical metadata
  are the template's hash-bound double-pass stability outputs.
- Assertions execute once per qualification. Each generation command requires
  exact successful assertion completion, executes fresh public ArtifactBuilder
  work, and compares against assertion exports and (for shipped) committed data.
  The template executes generation twice and invalidates changed output hashes.
  Generation results identify build/integrity obligations, never pytest calls.
- The standalone sentinel remains explicit; qualification folds its comparison
  into generation passes and schedules no redundant sentinel. No application
  cache is introduced. Failures clear generation completion before propagating.
- Pytest phase and public-build durations are measured diagnostics, never
  completion evidence. Shared setup cost belongs to its triggering test.
- Automatic qualification selects the shipped release on schema/generator
  paths. All declared releases remain available through explicit qualify.
- Runtime preparation writes an ignored input before the immutable checkpoint;
  verification observes and compares it, never refreshes it during execution.

Not for changing schema assertions, generating into the shipped directory,
activating policy, importing legacy records, or adding another cache framework.
