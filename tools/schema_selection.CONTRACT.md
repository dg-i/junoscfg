# schema_selection — contract

Application-owned execution relevance; native verification owns reusable success.

- Declared schema producers, validation algorithms, inputs and generation options
  select qualification. The audited source boundary binds all product sources,
  qualification adapters/fixtures and their transitive local import dependencies.
- Existing isolated consumer bodies may be normalized only when unchanged import
  structure and the reviewed producer relationship establish independence.
  Validator bodies are never consumer exemptions. New imports, callbacks and
  dynamic producer relationships require a fresh audit; execution cannot audit itself.
- Unreferenced tools, documentation, agent instructions, known workflow settings
  and release metadata are irrelevant. Explicit execution inputs win over these
  categories. Configuration binds known execution readers and unknown tool tables;
  ordinary gate settings and dependency release bookkeeping remain independent.
- Dependency projection binds the locked execution closure. Runtime identity binds
  actual schema libraries, pytest plugins and the shared engine module closure.
  Updating a checks updater or documentation alone does not change that identity.
- Negative decisions require valid native generation proof, current outputs and
  physical explicit inputs, equivalent execution boundary and actual runtime.
  Missing/corrupt/legacy proof, uncertain history or relevant identity mismatch
  selects qualification; stderr explains the failed condition or changed path.
- Historical body exemptions require exact receipt hashes; release configuration
  and lock comparisons may recover only hash-proven ancestor text.
- stdout is exactly the native selected boolean protocol. No skip override,
  evidence store, copied/relabelled proof, cross-machine trust or weakened ordinary
  tests, integrity, coverage or review is introduced.
