# schema_selection — contract

Application-owned relevance classification, called by native expensive-tier
selection. Native verification alone admits and publishes reusable success.

- Every declared producer, relevant input/dependency/configuration change and
  unknown path selects qualification. Missing/malformed history is uncertain.
- Existing consumer function bodies are exempt only with unchanged import-time
  AST and no calls/decorators/class hooks that could execute those bodies on import.
- Known workflow-only changes and solely editable-root version changes retain
  existing exceptions; the complete ordinary suite and cheap lock guard remain.
- Consumer independence is explicitly audited in consumer-boundary.json. Every
  other source byte and relevant dependency-lock field stays bound; new producer
  relationships require review, not merely another successful qualification.
- A negative decision also requires successful native generation evidence whose
  outputs, explicit inputs and actual executing engine still validate. Preparation
  metadata is never proof. Missing/corrupt/legacy evidence selects qualification.
- Prepared runtime is independently observed; native engine binds stdlib,
  dependency implementations, import paths/startup and relevant environment.
- Historical consumer exemptions require the compared old text to match the
  receipt's file hash. Unknown differences from prior proof select qualification.
- Successive root release-version exceptions may recover only exact hash-proven
  ancestor bytes for the three release files; other history remains conservative.
- stdout contains exactly the native selected boolean protocol. No evidence store,
  weakened assertions, mutation, cross-machine trust or app-owned cache is added.
