## MODIFIED Requirements

### Requirement: A statement the reader cannot complete is kept whole

WHEN a set or structured statement holds an entry whose key values run out, a key field without its keyword, a token after a terminal entry, `apply-groups` bare or with two names, `apply-macro` with a fourth value, a second, different value for a nokeyword leaf of a node that is no list, or a leaf without its value, THEN the reader SHALL create, replace and apply nothing from it, SHALL keep it whole from its keyword in the record its parent holds under the reserved key `junoscfg:unplaced` (`junoscfg.display.UNPLACED_STATEMENTS`), spelled as its original tokens joined by one space, quotes included, and field validation SHALL report it `UNPLACED`; an unknown token after a complete key of an entry with children stays in-entry. A kept statement SHALL never replace, join or hide a node the reader placed: a statement placed before or after it at the same level is placed and reports nothing. Every writer SHALL write a kept statement's text unchanged at its parent's path. A leaf without its value that arrives as JSON or YAML (`null`, `[null]`, `true`, `[]`) SHALL be reported `UNPLACED` and written as it stands; an empty XML element of a leaf the tree says takes a value SHALL read as the empty value `""`, as the device writes it, and field validation SHALL check `""` like any other value, so `""` on an enum, an integer type or a pattern it fails is reported and a string leaf takes it. A record whose text is not one line of words (a line break, a tab, a stray space, an unbalanced or inner quote, an unquoted `;`, `{`, `}`, `[` or `]`, a comment), that is empty, that holds a tag naming no meta command a writer writes, or whose shape is no record SHALL be refused with `ValueError` where JSON or YAML input is read, by the set and structured writers, and by the set reader for a statement it would keep so; field validation SHALL report such a record once; none of these messages SHALL name the statement. Anonymization, through `junoscfg.anonymize.anonymize()` and the conversion alike, SHALL treat a kept statement as content its walk cannot place (spec anonymization/placed-values, owner answer 5): its address-shaped words are replaced, its parent's schema path is named in a warning, and no message of the run SHALL carry its text. Path wildcards in `edityaml` SHALL pass the record by.
The same applies to `deactivate`, `activate`, `protect` and `delete`: a partial or surplus keyed-list key and an unknown path SHALL apply no attribute to the nearest valid parent or entry; the command SHALL be kept, with its original tokens, as `@<statement>` in the same record. A meta attribute addressed to an entire list the XSD marks `homogeneous` SHALL survive set output at that list path, as the device deactivates port-mirroring's `routing-instance` whole (deactivate6.txt); one addressed to another list's keyword without its entry's name SHALL be refused with `ValueError` ("Metadata commands cannot target a list without its entry's name"), as the QFX5120 25.2R2-S1.5 refuses `protect policy-options policy-statement` (probe D5) and set validation reports it invalid (`junoscfg.display.meta_target`, one walk for both; owner ruling 2026-10-17). A meta attribute on a positional value the reader placed is written back and reports nothing.

#### Scenario: Statements the device rejects

- **WHEN** `... as-path-neighbors as-list`, `... route-filter 198.51.100.0/24 next-policy`, `... as-list AS-LIST-A EXTRA`, `set apply-groups G1 G2`, bare `set apply-groups`, `virtual-link neighbor-id 10.255.255.3`, `virtual-link 10.255.255.4 0.0.0.2` or `apply-macro 12345 "KADJBF KU!H" balks XXXXX` is read
- **THEN** the parent's `junoscfg:unplaced` record holds it, set output reproduces it (device probe, vMX 23.2R2-S7.5, rejects each)

#### Scenario: A bare keyword beside the node it names

- **WHEN** `set apply-groups G1` and a bare `set apply-groups` are read, in either order, or a keyed entry and its list's bare keyword
- **THEN** the placed node keeps its value, the record holds the bare statement, only the bare one is reported `UNPLACED`, and set output writes both lines (OPEN-2)
- **WHEN** `apply-macro M1 a` and `apply-macro M1 a b c d`, or `apply-groups G0` and `apply-groups G1 G2`, are read
- **THEN** the placed node is unchanged and the kept sibling is the one report

#### Scenario: A leaf without its value

- **WHEN** `set system host-name router1` and a bare `set system host-name` are read in either order, `host-name;` stands in structured text, or `members` has no value
- **THEN** the leaf keeps its value, the record holds the bare statement, it is reported `UNPLACED` and strict conversion raises (NEW-C1; corpus `CORRECTLY_REJECTED`); an anonymized run converts it, the message's text withheld
- **WHEN** `"host-name"` arrives as JSON or YAML holding `null`, `[null]`, `true` or `[]`
- **THEN** it is reported `UNPLACED` and written as it stands; `description ""` and a presence leaf (`no-redirects`) in any spelling report nothing
- **WHEN** `<description></description>` or `<description/>` arrives as XML
- **THEN** it is `description ""`, as the device writes it in set and `""` in JSON (`tests/data/device/synthetic/vmx-23.2R2-S7.5/junoscfg-oracle.{set,json,xml}.gz`), it reports nothing, and strict conversion and anonymization pass (DEV-16)
- **WHEN** `<host-name/>`, a family `<mtu/>` or `<root-login/>` arrives as XML, or `""` for them as JSON or set
- **THEN** it is reported as an invalid value (pattern, integer, enum) and strict conversion raises

#### Scenario: A record is input like any other

- **WHEN** JSON or YAML carries a record whose text holds a line break, `; } snmp {` or an unquoted `]`, or a record that is empty, a string, a list, a statement with a value or a tag naming no meta command, or a set line would keep `a;b`
- **THEN** reading refuses it with `ValueError` naming no statement, a writer handed one by hand refuses it, and validation reports it once
- **WHEN** `anonymize()` or an anonymizing conversion meets a record holding `nonsense 203.0.114.9 SAMPLE-SECRET-GROUP`, read from set or JSON
- **THEN** the address is replaced in the statement's text, a tag on it is rewritten alike, the parent's schema path is named in a warning, `SAMPLE-SECRET-GROUP` is left as written, and no message carries the statement (owner answer 5; specification challenge S1)

#### Scenario: A kept statement keeps its quotes

- **WHEN** `set groups G1 apply-macro 12345 "KADJBF KU!H" balks XXXXX` or a meta command on a quoted unknown statement is read
- **THEN** set, structured, JSON and YAML output write the quoted token with its quotes, and the output reads back as the same record (OPEN-3)
- **WHEN** a kept meta command names no statement the record holds whole (alone, or a prefix of a kept statement)
- **THEN** set, JSON and YAML output carry it; structured output, which can tag only a statement it writes, leaves it out with a note

#### Scenario: Meta commands never fall back to a valid prefix

- **WHEN** any of the four meta commands addresses a partial or surplus `as-path-neighbors` key, or `deactivate system bogus-thing` is read
- **THEN** the command is kept whole and reported `UNPLACED`, and no parent or keyed entry receives its attribute

#### Scenario: A whole list carries a meta attribute

- **WHEN** a meta command addresses all of `system name-server` or of port-mirroring's `routing-instance`, homogeneous lists
- **THEN** set output writes that same meta command at the list path while its entries remain unchanged
- **WHEN** a meta command addresses all of `from as-path-neighbors`, `system login user` or `policy-options policy-statement`
- **THEN** set input is refused with `ValueError` naming a list without its entry's name
