## Purpose

A value written inside free text -- an address in a URL, a description or an annotation, a URL's user and password, a password hash in prose, an AS number in a name, a group named in an `apply-path` -- is the value of the rule that claims it, as it is where it stands alone. Anonymization replaces it by that rule, never rewrites what another rule wrote, and revert restores it exactly. Where a case is ambiguous, an anonymized run takes the safe side and replaces.

## ADDED Requirements

### Requirement: A value inside free text goes to the rule that owns its shape

WHEN the anonymize walker meets a string value that no rule replacing whole values takes (the password, SSH-key, community, identity, group, description and AS-number rules by their places), or the text of an annotation (`"@"`, `"@<key>"`), THEN it SHALL rewrite, rule by rule in the walker's order, each part of it a rule recognises by its shape: an address or prefix (the IP rule, under `ips`), including one at a sentence's end, after `lo_` or `host:`, zero-padded, and the IPv4 address inside an IPv4-mapped, -compatible or NAT64 IPv6 form, which takes its own replacement (S5); a URL's password and user, the userinfo running from `//` to the last `@` before the host and the user ending at its first `:`, any scheme in any case (the password rule under `passwords`, the identity rule under `identities`, with the pseudonym a login user of that name takes; S6); a password hash wherever it starts a word or follows punctuation; a sensitive word or pattern; and a configured AS number between non-digits and outside an address (the AS-number rule, under `as_numbers_in_strings`). It SHALL do so alike for a placed value, an annotation (S3) and content the walk cannot place, and SHALL never offer text one rule wrote to another rule. A part that is the whole value SHALL be replaced only where its rule takes the value: an address alone on a free-text leaf is replaced (S4), an SNMP OID (`snmp view V oid 1.3.6.1`) and an `areaid` reference (`from area 0.0.0.0`) are syntax and stay unless `ips_in_strings` is on. A value of the leaf's own enum stays, and `include`/`exclude` apply. No pass after the walk SHALL rewrite a value. Owner decisions accept S1/S3/S4/S6. S5 retains flat mappings: ambiguous spellings of the same IP address that share a replacement SHALL be rejected with a value-free error before anonymized output; unambiguous spellings SHALL reverse exactly.

#### Scenario: Free text under every door

- **WHEN** URLs (`scp://operator@...`, `FTP://Operator:Secret99@...`, `ftp://operator:p@ss:w0rd@...`,   `https://admin:secret98@[3ffe:b00::5]:8443/x`), prose with addresses (`see 203.0.114.6.`,   `lo_3ffe:b00::2`, `64:ff9b::203.0.114.5`, `203.000.114.006`) or hashes (`(key=$9$...)`), and an   annotation, written as set, curly (one-line, across lines, beside comments holding `;`, `{`, `}`   and quotes) or JSON, are anonymized by `anonymize()`, `convert_config` or `junoscfg convert`
- **THEN** no original survives on stdout or stderr, the text around it stays, and the dumped   mapping restores the original

#### Scenario: Syntax, another rule's text, and the filters

- **WHEN** `oid 1.3.6.1` and `from area 0.0.0.0` (`ignore_reserved` on) are anonymized with   `--anonymize-ips`, and `description "via 10.100.0.1 AS100"` with `--anonymize-as-numbers 100` and   its in-strings option
- **THEN** the OID and the area stay (with `--anonymize-ips-in-strings` the OID is rewritten:   NEW-R18, change 18); `AS100` is replaced and `10.100.0.1` stays whole (NEW-R17); a replacement is   never rewritten by another rule; a URL under an excluded path stays as written

### Requirement: An apply-path names configuration

WHEN the walker meets the value of an `apply-path` in scope of `include`/`exclude` (its own place decides, S7) THEN it SHALL read it against the schema tree from the configuration root, through transparent containers (`interfaces`, `routing-instances`): the word after a list's keyword is the value of that list's key field, even when it spells a keyword, and SHALL be offered to the rules as that key field's value at that path, so a name renamed elsewhere takes the same pseudonym and an address the same replacement; any other word is a keyword and SHALL stay; a wildcard there SHALL be treated as a wildcard name is (`anonymization/wildcard-names`) and reported by the `apply-path`'s schema path. Literal selectors SHALL also be checked against final names using literal equality. An excluded apply-path SHALL stay unchanged but its selector meaning SHALL still be checked. A changed selection in either filtering direction SHALL report only its schema path through `AnonymizeResult.patterns` and the conversion/CLI warning; harmless selectors SHALL not be reported. A path the tree cannot read to its end SHALL be content the walk cannot place: its words are rewritten by their shapes and its schema path is named in `AnonymizeResult.unplaced`.

### Requirement: Revert undoes each replacement once

WHEN `apply_revert` restores a value or a key THEN it SHALL first take a whole value the mapping records, then undo every other replacement the mapping records in one pass over the text, the longest first, a number only between non-digits and never inside an address, and every address last; a replacement SHALL never be undone twice nor depend on the mapping's order. A sensitive word's pseudonym SHALL be keyed by its spelling, so two spellings of one word get two pseudonyms and each reverts to its own; matching stays case-insensitive.

#### Scenario: AS numbers, prefixes and cases

- **WHEN** the mapping holds `64496` to `64497` and `64497` to `64498` and the text holds   `AS64497`, `AS6449712` and `64498`; or `netconanRemoved1` and `netconanRemoved10`; or `EBGP`   and `ebgp` were both anonymized under `--anonymize-sensitive-words ebgp`
- **THEN** revert gives `AS64496`, `AS6449712` and `64497`, the longer replacement's original, and   each case back, whatever the mapping's order (NEW-A-N5, NEW-R13)

#### Scenario: Ambiguous IP spellings

- **WHEN** plain/padded IPv4 or compressed/expanded/case IPv6 spellings of the same IP produce a shared replacement
- **THEN** anonymization fails before output with a value-free error, without changing caller IR; an ambiguous legacy IP map fails before revert mutation. Flat unambiguous maps still load and restore exactly.
