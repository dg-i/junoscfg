Set and structured output spell a value by its leaf's type. A one-term policy expression such as `import ( P-A )` is written bare, as the device writes it, where it was written `"( P-A )"`, a policy of that name; the device's quoted name `"( P-A )"` read from XML or JSON is written `"( P-A )"`, where it was written `""( P-A )""`, which did not load; and a value holding `"` is written with `\"`, as in `description "uplink to sw1 \"core\""`, where its inner quotes were written bare and the line did not load. Text that only looks like an expression on another leaf (a description) keeps its quotes. A policy-algebra value from XML or JSON that the readers would strip (`"P 1"`) is written `"\"P 1\""` so it reads back as held. Set validation accepts an escaped quote inside a quoted value, which the device prints, and still accepts a quoted value ending in a backslash. Complete quoted-name expressions may touch parentheses. An expression-shaped policy value that cannot safely occupy one command expression now raises `ValueError` before output, including schema-valid text that would introduce another statement.
