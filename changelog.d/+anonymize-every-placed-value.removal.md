Anonymizing content the schema cannot place no longer fails. An unknown key from JSON, YAML or XML, a statement kept whole from set or structured text, and a value of a shape its node does not take used to stop `convert_config(..., anon_config=...)` with `FieldValidationError` ("cannot anonymize") and `junoscfg convert --anonymize-*` with exit 1, while `junoscfg.anonymize.anonymize()` passed an unknown key unchanged and refused a kept statement with `ValueError`. Both now replace each word a rule knows by its shape alone (an address, a password hash, a sensitive word), leave every other word as written, and name each place by its schema path: `AnonymizeResult.unplaced`, and an `anonymize:` warning on stderr. A leaf without its value and an entry without its key field no longer fail an anonymized run either. In an anonymized run the text of a "could not be placed" validation message is withheld; `--strict` still fails. To stop on unplaced content, read those warnings or add `--strict`. More values are replaced than in 0.18.0, so dump and revert a mapping with the same release; `apply_revert` restores the words it replaced inside keys.
