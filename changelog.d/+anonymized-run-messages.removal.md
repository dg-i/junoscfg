An anonymized run (`convert_config(..., anon_config=...)` with a rule on, `junoscfg convert --anonymize-*`) no longer quotes the configuration in any message. Field-validation messages, in the diagnostics and in `FieldValidationError`, keep their path, reason and expected value and withhold the value (`FieldError.value` is `""`). A refusal to read the input (the set reader's bracket refusal, the structured reader's, a YAML, XML or JSON parse error) is raised as `ValueError` (`yaml.YAMLError` for YAML) saying the input could not be read, with its line where the parser gives one; a JSON parse error is no longer a `json.JSONDecodeError`, so catch `ValueError`. `junoscfg convert -v --anonymize-*` prints each validation error's line without its text or path; the structured writer's note on dropped tags gives their count; a pass-through collision names neither address; a failure no handler expects prints `Error: the conversion failed (<class>); details withheld: the run anonymizes` and exits 1 without a traceback. Exit codes are unchanged. To see the full messages, run the same conversion without anonymizing. Runs that do not anonymize, revert included, are unchanged.
