An anonymized run (`convert_config(..., anon_config=...)` with a rule on, `junoscfg convert --anonymize-*`) no longer quotes the configuration in any message. Field-validation messages, in the diagnostics and in `FieldValidationError`, keep their path, reason and expected value and withhold the value (`FieldError.value` is `""`). A refusal to read the input (the set reader's bracket refusal, the structured reader's, a YAML, XML or JSON parse error) is raised as `ValueError` (`yaml.YAMLError` for YAML) saying the input could not be read, with its line; catch `ValueError` and `yaml.YAMLError`, not their subclasses: a JSON parse error is no longer a `json.JSONDecodeError` (no `lineno`, `colno`, `pos`, `doc`), a YAML one no `MarkedYAMLError` (no `problem_mark`), and none carries a `__cause__`. Any other failure of an anonymized conversion is a `RuntimeError` naming only the original class, a pass-through collision included. `junoscfg convert -v --anonymize-*` prints each validation error's line without its text or path; the structured writer's note on dropped tags gives their count; a pass-through collision names neither address; a failure no handler expects prints `Error: the conversion failed (<class>); details withheld: the run anonymizes` and exits 1 without a traceback. Exit codes are unchanged. To see the full messages, run the same conversion without anonymizing. Runs that do not anonymize, revert included, are unchanged.
