Anonymization replaces a value written inside free text by the rule that owns it. Under `--anonymize-ips` an address inside a URL, a description, an `apply-path` or an annotation (`"@"` comments of JSON and YAML) is replaced without `--anonymize-ips-in-strings`, and so is an address that is the whole value of a free-text leaf (`description 203.0.114.9`); an SNMP OID and an area reference stay. The tokenizer now finds an address at a sentence's end, after `lo_` or `host:`, zero-padded, and the IPv4 address inside `::ffff:`, `::` and `64:ff9b::` forms. A URL's user is replaced under `--anonymize-identities` with the pseudonym a login user of that name takes, and its password under `--anonymize-passwords` (the userinfo runs to the last `@` before the host), as is a password hash in prose. An `apply-path` is read against the schema: its names take the pseudonyms of the names they name, so a prefix list still selects a renamed BGP group's neighbours, and its keywords are no longer rewritten by a sensitive word. A sensitive word's pseudonym now follows its spelling, so `EBGP` and `ebgp` revert each to its own. The passes after the walk are gone: one chain rewrites the shapes inside a value, never rewrites text another rule wrote (an AS number inside an address or a pseudonym), and honours `--anonymize-include`/`--anonymize-exclude`. Revert undoes each replacement once, longest first, a number only between non-digits, whatever the mapping's order. A wildcard under `--anonymize-as-numbers-in-strings` is reported only where a configured AS number can be spelled. The same configuration anonymized with the same salt differs from 0.20.x in those values; dump and revert with one release.
