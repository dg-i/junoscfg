Structured (curly) input is read by tokens, not lines. A block written on one line (`system { host-name router1; }`) converts and validates instead of yielding nothing; two statements or a closing brace and the next block on one line are no longer merged or dropped; a trailing `## a; b` or `/* a; b */` comment no longer joins the value; and a tagged one-liner is detected as structured, not YAML. Malformed curly text (an unmatched brace, an open block, bracket list, quote or comment, a statement without `;`) now raises `ValueError` naming the line, and the CLI exits 2. The device's `{ /* OMITTED */ }` placeholder for `apply-flags omit`, and any empty block, are reported as warnings (conversion diagnostics, `junoscfg convert`, `-v`, `audit unused`, `validate_structured`) instead of being written as configuration. `validate_structured` and `validate_config` check each curly statement as conversion reads it, so the device's one-line `hold-time up 2000 down 0;` and `protect:` lines validate, while `hold-time up 2000 down;` is rejected. New: `junoscfg.convert.structured_set_lines()` and the optional `diagnostic_sink` of `junoscfg.convert.to_dict()`.
