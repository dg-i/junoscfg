A statement the set or structured reader cannot place is kept as its own words, quotes included, and never meets a statement it did place. A bare `set apply-groups` after `set apply-groups G1` used to vanish, and before it the valid `G1` was reported as well; a bare `set system host-name` replaced the host name read before it with nothing and was written back without a word; `apply-macro 12345 "KADJBF KU!H" balks XXXXX` lost its quotes. Now each is written back as read and reported as not placed, and a leaf written without its value is reported from JSON and YAML too. From XML, an empty element of a leaf that takes a value (`<description></description>`) is the empty value, `description ""`, as the device writes it; it was a bare `description` the device rejects. `junoscfg.anonymize.anonymize()` refuses an IR whose `junoscfg:unplaced` record keeps a statement whole, as conversion already did, and neither refusal prints the statement.
