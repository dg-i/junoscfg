JSON and YAML output spell a statement the reader could not place differently: it is a key of the reserved mapping `"junoscfg:unplaced"` at its level (`"junoscfg:unplaced": {"apply-groups G1 G2": [null]}`) instead of a key of its own (`"apply-groups G1 G2": [null]`). Read kept statements from that mapping; `junoscfg.display.UNPLACED_STATEMENTS` names it. JSON or YAML written by an earlier release still reads as before, with one exception: an empty value 0.16.x read from XML (`<description></description>`) is `[null]` in the JSON or YAML it wrote and is now reported as a leaf without its value; regenerate it from the XML, or write `""` in its place. An empty value is now checked like any other: `""` on an enum, an integer or a pattern it fails (`host-name ""`) is reported, while a string leaf such as `description ""` takes it. A record whose text is not one line of words, or that is no mapping of statements, is refused with `ValueError` on read and by the set and structured writers, and a set statement that would be kept with an unquoted `;`, `{` or `}` is refused the same way.
