JSON and YAML output of set or structured `apply-flags omit` change shape: `"apply-flags": {"omit": [null]}` where 0.17.0 wrote `"apply-flags": "omit"` at the top level and `"junoscfg:unplaced": {"apply-flags omit": [null]}` below it. JSON or YAML written by 0.17.0 still reads: the old top-level value writes back the same set line and is now reported as a value where the schema has a container (the JSON schema rejects it at the top level), and the old record is reported as before; regenerate either from set or structured text. A set line with a word other than `omit` or `replace` after `apply-flags` is now rejected by `validate_config` and reported by conversion, where any value passed. `apply-flags replace` reads the same way as `omit`, its JSON and XML shape inferred until a device shows it. The four flag helpers in `junoscfg.display` take the schema node only, and the name tables behind them are gone; `junoscfg.display.UNIVERSAL_STATEMENTS` holds the nodes of the compatibility floor for a schema tree built before 0.8.0, read through `junoscfg.display.universal_statements()`.
