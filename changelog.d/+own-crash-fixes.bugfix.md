Three defects in junoscfg's own code are fixed. An absolute `--path` (or `convert_config(path=...)`) ending at a leaf or leaf-list now keeps that statement's tags, as the selection of its parent writes them, in every output format: `--path system.host-name` of a deactivated host name writes `deactivate system host-name` (structured `inactive:`, JSON and YAML `"@host-name"`), where it wrote the statement active; selected relative, a leaf's tags are written as a selected container's are (a bare `deactivate` in set output, a note in structured output). A `yaml` document with a mapping key that is not a string (`64496: x`, an unquoted `on: x`) is refused with its kind and path, as `yaml-new` refuses it ("a YAML int key at configuration has no JSON spelling", CLI exit 2, an invalid result from `-v`), where conversion and audit crashed with `AttributeError` and validation with `TypeError`; quote such a key. JSON input nested more than 64 levels deep is refused with its path ("a JSON value at ... is nested deeper than 64 levels", CLI exit 2), where junoscfg crashed with `RecursionError` past about 450 levels; no Junos configuration nests deeper than about 26.
