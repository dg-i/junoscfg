Set validation no longer rejects junoscfg's own output. A nokeyword *presence* node — `prefix-list-item` and 203 others — kept a keyword that set commands never write, so `set policy-options prefix-list PL-A 10.0.0.0/8`, which `junoscfg convert -e set` emits, failed `junoscfg convert -v`. Regenerating the artifacts with `--regen-schema` also no longer conflicts with the grammar reproducibility check: the grammar is now built from the structure tree shipped beside it.
