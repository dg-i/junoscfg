List entries are now keyed by the identifiers the device declares, in declared order: `from as-path-neighbors as-list <name>` keeps its list name on set and structured input, `attributes-match` carries its three fields, and route-filter, source-address-filter and prefix-list-filter entries are keyed by address and match type with their actions as children. **Breaking** for JSON and YAML consumers: the 171 lists keyed by one other field and the 64 keyed by several are written with those fields where `name` stood, and `ENTRY_KEY_OVERRIDES` and `get_flat_entry_config` leave `junoscfg.display` (read `entry_keys()` instead). A set statement the reader cannot complete, `apply-groups G1 G2` among them, is kept whole and reported as unplaced rather than partly applied.

Lists the XSD bounds by a number (`forwarding-classes class`, `commit peers`) are lists: three forwarding classes no longer collapse into the last, and a second, different value for a single node's nokeyword leaf is kept whole and reported rather than written over the first. A key field given by keyword (`virtual-link neighbor-id ... transit-area ...`) is read in either order and written with its keyword. A `name` key's enum is open again, so `classifiers dscp <name>` validates clean. An entry from JSON, YAML or XML missing a key field, a bare `set apply-groups` and an `apply-macro` with a fourth value are reported unplaced, and set validation takes `apply-macro` with one to three values. Large set inputs convert faster: entries are found by key, not by scanning the list.

Anonymization fix: a value from its leaf's own enum is configuration syntax and passes every rule unchanged. With `--anonymize-sensitive-words bgp`, 0.14.0 turned `from protocol bgp` into `from protocol word_<hash>`, which the device rejects.
