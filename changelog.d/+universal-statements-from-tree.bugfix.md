`apply-flags omit` reads as the device writes it, `{"apply-flags": {"omit": [null]}}`, from set and structured input at every level, as JSON, YAML and XML already did. Below the top level it used to be reported as a statement that could not be placed, so `--strict` failed and anonymization refused the configuration; at the top it read as the leaf `"omit"`. The four statements valid at every level (`apply-groups`, `apply-groups-except`, `apply-flags`, `apply-macro`) are now read from the schema tree by every reader, writer and field validation: XML and YAML read a nested `apply-groups` with one group as a list, as the device's JSON writes it, and field validation checks a nested one against its node, reporting a flag `apply-flags` does not hold or an `apply-flags` with no flag. Content the schema cannot place is written with every keyword it holds; a table of element names used to drop some (`set bogus-container 5` for `timeout 5`).
