Set input is what a device exports (`show configuration | display set`), and junoscfg now says so: the constructs it does not read are listed in the conversion guide and refused by name. Set validation (`-v`) and the set reader judge a `deactivate`, `protect`, `activate` or `delete` line by one walk of the schema: a line that stops at a list's keyword without the entry's name (`protect policy-options policy-statement`), names a leaf's value or one value of a leaf-list (`deactivate ... community 64496:2`), or stops inside an entry's key is invalid, as a QFX5120 refuses it, where `-v` said OK; conversion refuses the first two with an error naming them. A list the schema marks homogeneous (`system name-server`, port-mirroring `routing-instance`) is still tagged whole. A set line holding several statements that each stand alone (`hold-time up 0 down 0`) is reported "Unsupported in set input, one statement a line" by `-v`, and conversion reads it. `-v` takes `then community = | + | - NAME`, as the device writes it, where it took only the misspellings `eq_literal`, `plus_literal` and `minus_literal`. An absolute `--path` keeps the tags of every statement along the path, so a leaf under `deactivate system` is written inside the deactivated statement, as the device prints it, where it was written active. A relative `--path` drops a tag at or above the path with one note in every format ("N tag(s) at or above the selected path dropped"), where set output wrote a bare `deactivate` or `protect` the device refuses and JSON and YAML dropped it silently; the set writer now gives notes, named `set-output`, and every writer's note source is named after it. Set and structured output note a tag on one value of a leaf-list, which Junos has no form for, where they dropped it silently. Validation takes grpc `clear-text address`, `system dump-on-panic`, `system debugger-on-break`, `system debugger-on-panic` and `chassis dump-on-panic`, which a QFX5120 takes and prints inside `<undocumented>`.
